> 2026-09-20 深夜 ~ 凌晨。目标: 717ms/帧 → ~580ms (PS写包与PL发包重叠)。
> 当前状态: **未完成** — 数据错位未根治, 板上跑的是探针版。

## 背景基线 (Step1 之前, 已验证)

```
组合: BIT 0C0A700E + ELF 648A4276 (快照+仪表盘+v5节奏)
成绩: 827/827 miss=0, 717ms/帧, 画面活无撕裂 (700帧压测稳定)
瓶颈: 每包867μs = PS填BRAM 700μs(80%) + 线路发送110μs + 轮询
目标: 写包N与发包N-1重叠 → 每包≈700μs → ~580ms/帧
```

## 轮次记录

### R1: 双 bank + CTRL bit2 预置 (BIT B5CEB3F1)
**改动:**
- RTL: mem 拆 mem_bank0/1 (各512字), 写按 ram_wa_ps 高位分 bank
- RTL: CTRL bit2 = bank 预置, serve 时锁存 tx_bank_eth
- PS: write_bram_pb(bank), 每包 CTRL(bank<<2) → 写 → TXSTART → 等busy=0

**现象:** got=414/827 (精确一半), 细横条百叶窗
**分析:** 奇数包(bank1)内容坏 → RK 按 fid/tot 过滤丢弃
**教训:** busy=1 期间 TXSTART 被吞 → 但 700μs写 > 110μs发, 吞的概率应低 — 未定论

### R2: 方案B — 触发后等 busy=1 (纯 ELF 8196CD61)
**改动:** TXSTART 后先等 ST_TX_BUSY 置位再写下一包
**现象:** 完全不变 (仍 414)
**结论:** 触发竞态不是根因 → 排除"触发被吞"假说

### R3: One-hot 双线 TXSTART + pending 受理缓存 (BIT 35660345)
**改动:**
- RTL: TXSTART(0x08)=bank0 / TXSTART1(0x18)=bank1, 各自独立2FF同步链
- RTL: serve 时 tx_bank_eth <= tx_start1_pulse (哪条线=哪个bank)
- RTL: pending 缓存 (busy期间触发存起, 发完自动发)
- PS: 触发按 bank 选地址, 删 CTRL 预置, 删等受理
**现象:** 仍 414/827
**抓包:** 偶数包(fid/tot/idx)完全正确, 奇数包 fid 字段=垃圾
**结论:** bank0 读写全对; bank1 的包内容坏 → 集中查 bank1 路径

### R4: bank 位修正 bit12→bit10 (BIT A72255FC)
**分析:** bank 位取 ram_wa_ps[C_BRAM_AW]=bit10, 但 bank 偏移 0x800=bit11 → 错位
**改动:** wbank=bit10, waddr=[9:2] (当时认为的正确映射)
**现象:** 不变
**发现:** 抓包显示 fid=0x0052=帧号82 ✓ tot=827 ✓ — 偶数包全对, 但洞变 8 字节!

### R5: bank 位修正 bit10→bit11 (BIT 83C77E26)
**改动:** wbank=bit11, waddr=[10:2] (回到最初映射, 认为这才是对的)
**现象:** 不变, 仍 414
**抓包(DIAG图案):** 线上 = [8B零洞][pb[6]起数据] — 头6字节被吞!
**关键读数:** 偏移 = +2字 (不是 v5 的 +1字)

### R6: off-by-zero 对照实验 (BIT E42FB60D)
**改动:** 写端 +1 删除 (mem_bank[waddr_d] 直接写)
**现象:** **线上完全不变!** (+0 和 +1 一字不差)
**结论(重大):** RTL 的 +1 根本没生效 → 洞不是 off-by-one 造成!
            写端存在独立的 +2 字错位, 与 +1 无关

### R7: 诊断寄存器 + 写读自检 (BIT 67FBD216 + ELF 94D1F9DF)
**改动:**
- RTL: RAM_RD(0x1C)/RAM_RDD(0x20)/DBG(0x24) 诊断寄存器
- PS: 上电写16字图案到双bank → 逐字读回验证 → LED报错
**现象:** LED=0011 (双bank 16/16 全错!)
**读回:** got=0x00000000 (全零), exp 含正确图案
**结论:** 读回全零 + 线上有数据 → **诊断口和写端共用捕获链, 同源滞后**

### R8: 地址链根治 — 预载+自增 (BIT 175D04A5 + ELF 5B0ADA42)
**改动:**
- RTL: RAM_WA 译码时预载 bram_waddr_d 起点 (消灭捕获滞后)
- RTL: RAM_WD 地址自增 +1 (与数据同拍, 不依赖 ram_wa_ps)
- RTL: 读端 rd_lo+1 (保持4B洞, RK SKIP=4 兼容)
- PS: 自检哑读修复 (RAM_RD 后读两次)
**现象:** **0/827!! 全部解析失败**
**抓包:** 线上仍 [8B零洞][pb[6]起] — 与 R5 完全相同!
**时间线验证:** RTL 03:21 → DCP 03:24 → BIT 03:33 — 修正确实进了 bit
**结论(未解):** 写端预载+自增后线上纹丝不动 → 偏移源头不在 bram_waddr_d!

## 当前认知边界 (R8 后)

**确定的事实:**
1. 线上偏移恒 +2字 (8B洞+头6B被吞), R4~R8 全部相同
2. off-by-one (+1) 对线上零影响 → 不是洞的成因
3. 写端地址链重写 (预载+自增) 对线上零影响 → 偏移在更上游!
4. 诊断口读回全零 → 诊断口与写端同源坏
5. bank0 的 fid/tot/idx 在 R3/R4 曾完全正确 → 数据链路本身能对

**待排除的嫌疑 (按优先级):**
- **S1: AXI 译码 have_addr/have_data 捕获链吞掉前2个 wr_fire**
  (RAM_WA 设置后的头两次 RAM_WD 写没有执行 → pb字0,1 丢失)
  支持证据: R8 自增改写后线上不变 = 偏移在 wr_fire 生成层, 不在地址计算层
- S2: PS 端 Xil_Out32 连续写的前两次被 AXI 互连吃掉 (GP口合并?)
- S3: 诊断口滞后与写端滞后同源 → 都指向 wr_fire 捕获链

**下一步 (已写好探针, 待烧录):**
最小单字探针 (ELF 已含): 写 0xDEAD0000 到字0 → 扫读字0..7 找落位
                        写 0xBEEF0000 到字4 → 扫读
                        写 0xC0DE0000 到 bank1 字0 → 读回
结果直接读出: 写落位偏移量 + 诊断口偏移量 + bank 路由
**注意: 探针结果经包0数据区上线, 但线上偏移+2仍在 → 读数时要 mentally 校正!**

## 方法论教训 (本轮新增)

1. **线上字节级抓包是最硬的证据** — "got=414"只能看到一半丢失,
   DIAG图案+hex dump 直接读出偏移量和内容
2. **对照实验要选零耦合变量** — off-by-zero 实验证明 +1 无效,
   一举排除一条整错误路径
3. **"修正进了源码"≠"修正进了bit"** — 每轮必须验证: 源码含修正
   → 时间线(RTL改于BIT前) → (理想:综合日志含信号名)
4. **自检仪器本身也要被验证** — R7 的 16/16 全错一半是仪器bug(哑读缺失),
   先修仪器再信读数
5. **连续 Xil_Out32 的前几拍行为是未审计区** — AXI-Lite 从机的
   have_addr/have_data 捕获链对背靠背写的行为需要探针数据定论
